# # LOG 0 베이스라인 검증 및 수정

## 1. 개요

기존 XGBoost 베이스라인 모델 코드를 재검증하는 과정에서

`feature_cols`에 사용된 일부 컬럼명이 실제 parquet 데이터의 컬럼명과 일치하지 않는 문제를 확인하였다.

## 2. 문제 확인

기존 코드에서는 아래 컬럼들을 사용하고 있었다.

* `점포_수`
* `유사_업종_점포_수`
* `개업_율`
* `폐업_률`
* `프랜차이즈_점포_수`

하지만 실제 parquet 데이터에서는 merge 과정에서 동일 컬럼명이 중복되며 pandas가 자동으로 `_x`, `_y` suffix를 부여한 상태였다.

따라서 실제 데이터에는 아래와 같이 저장되어 있었다.

* `점포_수_y`
* `유사_업종_점포_수_y`
* `개업_율_y`
* `폐업_률_y`
* `프랜차이즈_점포_수_y`

기존 컬럼명으로는 feature를 찾지 못해 모델 학습 시 오류가 발생하였다.

## 3. 수정 사항

기존 feature 컬럼명을 실제 parquet 데이터 기준으로 수정하였다.

### 수정 전

```
'점포_수',
'유사_업종_점포_수',
'개업_율',
'폐업_률',
'프랜차이즈_점포_수'
```

### 수정 후

```
'점포_수_y',
'유사_업종_점포_수_y',
'개업_율_y',
'폐업_률_y',
'프랜차이즈_점포_수_y'
```

---

## 4. 실험 설정

### 데이터 분할

* Train : 2019 ~ 2023
* Test : 2024

시계열 기반 분할(Time-Series Split) 방식을 적용하였다.

### 모델

* XGBoost Classifier 사용
* 클래스 불균형 문제를 완화하기 위해 `scale_pos_weight` 적용

---

## 5. 실험 결과

### 성능 지표

* AUC Score : **0.9055**
* Accuracy : **0.8217**

### Classification Report

```

1       0.13      0.85      0.23      2705
```

---

## 6. 결과 분석

### 주요 특징

* 위험 상권(1)에 대한 Recall은 높게 나타남
* 반면 Precision은 낮게 나타남
* 즉, 실제 위험 상권은 많이 탐지하지만 정상 상권도 위험으로 과다 예측하는 경향 존재

### 중요 변수(Feature Importance)

상위 중요 변수는 다음과 같았다.

1. `전년_동기_대비_폐업_증감률`
2. `점포당_평균_매출`
3. `상권_전체점포_수`
4. `당월_매출_금액`
5. `유사_업종_점포_수_y`
6. `폐업_률_y`

특히 `전년_동기_대비_폐업_증감률`이 압도적으로 높은 중요도를 보였다.

# # LOG 1 소득구간 및 상권-업종 적합도 변수 추가 실험

## 1. 개요

기존 XGBoost 베이스라인 모델에 소비 기반 파생 변수인 `소득_구간_코드`, `상권_업종_적합도`를 추가하여 성능 변화를 비교하였다.

서울시 소비 API(`trdarNcmCnsmp`) 데이터를 활용하여 상권별 소비 패턴을 수집하였으며, 업종별 소비 성향과 연결되는 비율 데이터를 기반으로 상권-업종 적합도를 생성하였다.

---

## 2. 추가 변수 생성 과정

### 추가 변수

* `소득_구간_코드`
* `상권_업종_적합도`

### 소비 데이터 활용

서울 열린데이터 API 소비 데이터를 활용하여 다음 비율 데이터를 생성하였다.

* 식료품비율
* 의류비율
* 생활용품비율
* 의료비율
* 교통비율
* 여가문화비율
* 교육비율
* 유흥비율

이후 업종별 특성에 따라 적절한 소비 비율을 매핑하여 `상권_업종_적합도`를 생성하였다.

### 업종별 매핑 예시

* 한식음식점 → 식료품비율
* 호프-간이주점 → 유흥비율
* 일반교습학원 → 교육비율
* 일반의류 → 의류비율
* 일반의원 → 의료비율

---

## 3. 데이터 처리

### API 데이터 범위

API 테스트 결과 소비 데이터는 `20251` 분기까지 존재하는 것을 확인하였다.

### 결측 처리

다음 조건의 데이터는 제거하였다.

* `상권_업종_적합도 == 0`
* `상권_업종_적합도` 결측치(NaN)

이를 통해 실제 소비 데이터가 존재하는 상권만 학습 데이터에 사용하였다.

---

## 4. 실험 설정

### 데이터 분할

* Train : 2019 ~ 2023
* Test : 2024

시계열 기반(Time-Series Split)으로 분할하였다.

### 모델 설정

* XGBoost Classifier 사용
* 클래스 불균형 완화를 위해 `scale_pos_weight` 적용

### 추가된 Feature

# # LOG 2 아파트 기반 변수 추가 실험

## 1. 개요

기존 XGBoost 모델에 상권 주변 주거 특성을 반영하기 위해

서울시 상권분석서비스(아파트-상권) API 데이터를 활용하여 아파트 관련 변수를 추가하였다.

상권별 주거 규모와 자산 수준이 상권 과포화 위험에 영향을 줄 수 있다고 판단하여 실험을 진행하였다.

* 서울시 상권분석서비스(아파트-상권)
* `InfoTrdarAptQq`

### 추가 변수

* `총_아파트_세대수`
* `아파트_평균_시가`

### 변수 생성 방식

### 총 아파트 세대수

* 아파트 규모 및 시가 정보는 상권 특성을 일부 설명할 수는 있었으나,
  실제 과포화 위험 예측에는 영향력이 제한적인 것으로 판단된다.
* 상권 과포화는 단순 주거 규모보다
  실제 소비 활동, 유동성, 경쟁 강도 등의 영향을 더 크게 받을 가능성이 존재한다.

* 특히 아파트 변수보다 실제 상권 소비 활동과 더 직접적으로 연결되기 때문에 성능 향상 방향성이 상대적으로 긍정적으로 나타난 것으로 보인다.
* 다만 상권 과포화 위험 예측에서는 여전히 `전년_동기_대비_폐업_증감률`, `점포당_평균_매출`, `폐업_률_y` 등의 기존 핵심 변수 영향력이 압도적으로 크게 유지되었다.

---

## 8. 향후 계획

* 핵심변수에 압도적으로 크게 의존하고 있으므로, 새 변수를 추가하기 보단 XGBOOST 파라미터를 수정해보며 실험을 진행해볼것이다.

# # LOG 4 XGBoost 파라미터 튜닝 실험

## 1. 개요

기존 실험에서는 새로운 외부 변수 및 파생변수를 지속적으로 추가하였으나

성능 향상이 매우 제한적으로 나타났다.

특히 상권 과포화 위험 예측에서

기존 핵심 변수들의 영향력이 지나치게 강하게 유지되는 현상이 반복적으로 관찰되었다.

이에 따라 단순 Feature 추가보다

XGBoost 모델 자체의 학습 구조와 일반화 성능을 조정하는 방향으로 실험을 진행하였다.

---

## 2. 실험 목적

### 기존 문제점

기존 모델은 아래 변수들에 지나치게 의존하는 경향을 보였다.

* `전년_동기_대비_폐업_증감률`
* `점포당_평균_매출`
* `당월_매출_금액`
* `폐업_률_y`

이로 인해:

* 특정 변수 중요도가 과도하게 높아짐
* 새로운 변수들이 충분히 학습되지 못함
* 모델 일반화 성능 향상 한계 발생

문제를 완화하기 위해

XGBoost의 복잡도 및 규제 파라미터를 조정하였다.

---

## 3. 변경한 파라미터

### 기존 설정

```
XGBClassifier(

learning_rate=0.05,

)
```

### 튜닝 후 설정

```
XGBClassifier(

reg_alpha=1,

scale_pos_weight=ratio,
random_state=42,
eval_metric='auc'
)
```

---

## 4. 파라미터 조정 의도

### max_depth 감소

```
max_depth=5→4
```

* 트리 복잡도를 줄여 과적합 완화
* 특정 변수에 대한 과도한 분기 방지

### learning_rate 감소

```
0.05→0.03
```

* 학습을 더 천천히 진행
* 일반화 성능 향상 유도

### n_estimators 증가

```
200→400
```

* 낮아진 learning rate 보완
* 더 안정적인 학습 수행

### subsample / colsample_bytree 추가

```
subsample=0.8
colsample_bytree=0.8
```

* 데이터 및 feature 일부만 랜덤 사용
* 변수 편향 감소 유도

### gamma / min_child_weight 추가

```
gamma=0.2
min_child_weight=3
```

* 의미 없는 분기 생성 억제
* noise 감소 목적

### 정규화 강화

```
reg_alpha=1
reg_lambda=15
```

* 특정 변수에 과도하게 의존하는 현상 완화 시도

# # LOG 5 덴시티(Density) 기반 파생변수 추가 실험

## 1. 개요

기존 XGBoost 모델에 상권 내부의 상대적 경쟁 강도와 소비 밀집도를 반영하기 위해

Density 기반 파생변수를 추가하였다.

기존 변수들은 절대적인 규모 중심 정보가 많았기 때문에,

이번 실험에서는 실제 상권 내 경쟁 밀집도와 점포 효율성을 반영할 수 있는 변수들을 생성하여

과포화 위험 예측 성능 향상 여부를 검증하였다.

---

## 2. 추가 변수 생성 과정

### 추가 변수

* `직장인구_100명당_점포수`
* `아파트_100세대당_점포수`
* `유사업종_점포비율`
* `직장인구_100명당_유사업종수`
* `점포당_매출_밀도`
* `직장인구_1인당_매출`
* `아파트세대당_매출`

---

## 3. 변수 생성 방식

### 직장인구 대비 점포 밀도

```
직장인구_100명당_점포수=
(점포_수_y/총_직장_인구_수)*100
```

### 아파트 세대 대비 점포 밀도

```
아파트_100세대당_점포수=
(점포_수_y/총_아파트_세대수)*100
```

### 유사업종 밀집도

```
유사업종_점포비율=
유사_업종_점포_수_y/상권_전체점포_수
```

### 직장인구 대비 유사업종 밀도

```
직장인구_100명당_유사업종수=
(유사_업종_점포_수_y/총_직장_인구_수)*100
```

### 점포당 매출 밀도

```
점포당_매출_밀도=
당월_매출_금액/점포_수_y
```

### 인구 기반 매출 효율성

```
직장인구_1인당_매출=
당월_매출_금액/총_직장_인구_수
```

```
아파트세대당_매출=
당월_매출_금액/총_아파트_세대수
```
