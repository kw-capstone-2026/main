프론트에서 SHAP 결과는 개별 점포 상세 페이지에서 “위험도 % + 위험 상승 요인/안정 요인 막대차트” 형태로 보여주면 좋을것같습니다. 지도에서 점포 선택 → 상세 진단 페이지 이동 흐름이면 발표 시에도 보기 편할 것 같습니다.

메인 화면에서는:
서울 지도 + 상권 마커 표시
업종/위험도 필터
검색창(상권명, 업종)
형태로 구성하고, 마커 클릭 시 상세 페이지로 이동해서 해당 점포 분석 결과를 보여주는 구조가 직관적일 것 같습니다.
상세 진단 페이지에서는:
상단
점포명 / 업종 / 지역
폐업 위험도 % (게이지 or 큰 배지)
“고위험 / 보통 / 안정” 상태 표시
중간
SHAP 기반 위험 요인 차트
빨강: 폐업 위험 증가 요인
파랑: 안정 기여 요인
예:
임대료 상승 ↑
유동인구 감소 ↑
직장인구 증가 ↓
이런 식으로 막대그래프 형태 시각화
하단
주변 상권 통계 카드
평균 매출 변화
최근 폐업률
유동인구 변화율
유사 업종 비교 그래프
정도로 구성하면 좋을것 같습니다.

그리고 실시간 추론보다는 주요 상권 결과를 미리 계산해 캐싱해두는 방식이 현재 일정상 더 현실적이라고 생각합니다. 발표 때 속도나 서버 안정성 측면에서도 유리할 것 같습니다. 실시간 계산은 이후 확장 방향으로 설명해도 충분할 것 같습니다.

백엔드는 제가 정확히 알고 있는 부분은 아니지만, 일정상 우선 프론트에서 FastAPI를 직접 호출하는 방식으로 빠르게 연결한 뒤, 시간 여유가 생기면 Spring Gateway 형태로 정리하는 방향이 좋아 보입니다. 발표 전까지는 구조 완성도보다 안정적으로 시연 가능한 상태를 우선 확보하는 게 중요할 것 같습니다.

다음주까지 프로젝트 최종 발표를 완성해야하니 우선은 복잡한 기능보다 발표 시연이 가능한 완성형 흐름을 먼저 만드는 방향이 좋을 것 같습니다.
