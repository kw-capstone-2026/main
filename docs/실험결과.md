# LOG 0 베이스라인 검증 및 수정

## 1. 개요

기존 XGBoost 베이스라인 모델 코드를 재검증하는 과정에서  
`feature_cols`에 사용된 일부 컬럼명이 실제 parquet 데이터의 컬럼명과 일치하지 않는 문제를 확인하였다.

---

## 2. 문제 확인

기존 코드에서는 아래 컬럼들을 사용하고 있었다.

- `점포_수`
- `유사_업종_점포_수`
- `개업_율`
- `폐업_률`
- `프랜차이즈_점포_수`

하지만 실제 parquet 데이터에서는 merge 과정에서 동일 컬럼명이 중복되며 pandas가 자동으로 `_x`, `_y` suffix를 부여한 상태였다.

따라서 실제 데이터에는 아래와 같이 저장되어 있었다.

- `점포_수_y`
- `유사_업종_점포_수_y`
- `개업_율_y`
- `폐업_률_y`
- `프랜차이즈_점포_수_y`

기존 컬럼명으로는 feature를 찾지 못해 모델 학습 시 오류가 발생하였다.

---

## 3. 수정 사항

기존 feature 컬럼명을 실제 parquet 데이터 기준으로 수정하였다.

### 수정 전

```python
'점포_수',
'유사_업종_점포_수',
'개업_율',
'폐업_률',
'프랜차이즈_점포_수'
```

### 수정 후

```python
'점포_수_y',
'유사_업종_점포_수_y',
'개업_율_y',
'폐업_률_y',
'프랜차이즈_점포_수_y'
```

---

## 4. 실험 설정

### 데이터 분할

- Train : 2019 ~ 2023
- Test : 2024

시계열 기반 분할(Time-Series Split) 방식을 적용하였다.

### 모델

- XGBoost Classifier 사용
- 클래스 불균형 문제를 완화하기 위해 `scale_pos_weight` 적용

---

## 5. 실험 결과

### 성능 지표

- AUC Score : **0.9055**
- Accuracy : **0.8217**

### Classification Report

```text
precision    recall  f1-score   support

0       0.99      0.82      0.90     84474
1       0.13      0.85      0.23      2705
```

---

## 6. 결과 분석

### 주요 특징

- 위험 상권(1)에 대한 Recall은 높게 나타남
- 반면 Precision은 낮게 나타남
- 즉, 실제 위험 상권은 많이 탐지하지만 정상 상권도 위험으로 과다 예측하는 경향 존재

### 중요 변수(Feature Importance)

상위 중요 변수는 다음과 같았다.

1. `전년_동기_대비_폐업_증감률`
2. `점포당_평균_매출`
3. `상권_전체점포_수`
4. `당월_매출_금액`
5. `유사_업종_점포_수_y`
6. `폐업_률_y`

특히 `전년_동기_대비_폐업_증감률`이 압도적으로 높은 중요도를 보였다.

---

## 7. 향후 계획
다양한 변수를 붙이며 더 나은 모델 조정을 위한 실험 진행



# LOG 1 소득구간 및 상권-업종 적합도 변수 추가 실험

## 1. 개요

기존 XGBoost 베이스라인 모델에 소비 기반 파생 변수인 `소득_구간_코드`, `상권_업종_적합도`를 추가하여 성능 변화를 비교하였다.

서울시 소비 API(`trdarNcmCnsmp`) 데이터를 활용하여 상권별 소비 패턴을 수집하였으며, 업종별 소비 성향과 연결되는 비율 데이터를 기반으로 상권-업종 적합도를 생성하였다.

---

## 2. 추가 변수 생성 과정

### 추가 변수

- `소득_구간_코드`
- `상권_업종_적합도`

### 소비 데이터 활용

서울 열린데이터 API 소비 데이터를 활용하여 다음 비율 데이터를 생성하였다.

- 식료품비율
- 의류비율
- 생활용품비율
- 의료비율
- 교통비율
- 여가문화비율
- 교육비율
- 유흥비율

이후 업종별 특성에 따라 적절한 소비 비율을 매핑하여 `상권_업종_적합도`를 생성하였다.

### 업종별 매핑 예시

- 한식음식점 → 식료품비율
- 호프-간이주점 → 유흥비율
- 일반교습학원 → 교육비율
- 일반의류 → 의류비율
- 일반의원 → 의료비율

---

## 3. 데이터 처리

### API 데이터 범위

API 테스트 결과 소비 데이터는 `20251` 분기까지 존재하는 것을 확인하였다.

### 결측 처리

다음 조건의 데이터는 제거하였다.

- `상권_업종_적합도 == 0`
- `상권_업종_적합도` 결측치(NaN)

이를 통해 실제 소비 데이터가 존재하는 상권만 학습 데이터에 사용하였다.

---

## 4. 실험 설정

### 데이터 분할

- Train : 2019 ~ 2023
- Test : 2024

시계열 기반(Time-Series Split)으로 분할하였다.

### 모델 설정

- XGBoost Classifier 사용
- 클래스 불균형 완화를 위해 `scale_pos_weight` 적용

### 추가된 Feature

```python
'소득_구간_코드',
'상권_업종_적합도'
```

# LOG 2 아파트 기반 변수 추가 실험

## 1. 개요

기존 XGBoost 모델에 상권 주변 주거 특성을 반영하기 위해  
서울시 상권분석서비스(아파트-상권) API 데이터를 활용하여 아파트 관련 변수를 추가하였다.

상권별 주거 규모와 자산 수준이 상권 과포화 위험에 영향을 줄 수 있다고 판단하여 실험을 진행하였다.

---

## 2. 추가 변수 생성 과정

### 사용 API

- 서울시 상권분석서비스(아파트-상권)
- `InfoTrdarAptQq`

### 추가 변수

- `총_아파트_세대수`
- `아파트_평균_시가`

### 변수 생성 방식

#### 총 아파트 세대수

아래 면적별 세대 수를 합산하여 생성하였다.

```python
AE_66_SQMT_BELO_HSHLD_CO
AE_66_SQMT_HSHLD_CO
AE_99_SQMT_HSHLD_CO
AE_132_SQMT_HSHLD_CO
AE_165_SQMT_HSHLD_CO
```

#### 아파트 평균 시가

API의 `AVRG_MKTC` 값을 그대로 사용하였다.

---

## 3. 데이터 처리

### 데이터 병합 기준

아파트 데이터는 업종 단위가 아닌 상권 단위 데이터이므로 아래 키를 기준으로 병합하였다.

```python
['기준_년분기_코드', '상권_코드']
```

### 결측 처리

병합 이후 결측치는 모두 `0`으로 처리하였다.

```python
fillna(0)
```

---

## 4. 실험 설정

### 데이터 분할

- Train : 2019 ~ 2023
- Test : 2024

시계열 기반(Time-Series Split)으로 분할하였다.

### 모델 설정

- XGBoost Classifier 사용
- 클래스 불균형 완화를 위해 `scale_pos_weight` 적용

### 추가된 Feature

```python
'총_아파트_세대수',
'아파트_평균_시가'
```

---

## 7. 결과 분석

| 항목 | LOG 1 | LOG 2 |
|---|---|---|
| AUC | 0.9068 | 0.9062 |
| Accuracy | 0.8218 | 0.8227 |

### 분석

- Accuracy는 소폭 상승하였다.
- 반면 AUC는 약간 감소하였다.
- 추가한 아파트 변수는 Top 10 중요 변수에 포함되지 않았다.
- 기존 상권 관련 변수들의 영향력이 여전히 매우 강하게 나타났다.
- 특히 `전년_동기_대비_폐업_증감률`, `점포당_평균_매출`, `폐업_률_y` 등이 핵심 변수로 유지되었다.

### 해석

- 아파트 규모 및 시가 정보는 상권 특성을 일부 설명할 수는 있었으나,
  실제 과포화 위험 예측에는 영향력이 제한적인 것으로 판단된다.
- 상권 과포화는 단순 주거 규모보다
  실제 소비 활동, 유동성, 경쟁 강도 등의 영향을 더 크게 받을 가능성이 존재한다.
