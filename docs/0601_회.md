## 📌 1. 실시간 가상 시뮬레이션을 위한 캐스케이드(Cascade) 아키텍처

우리가 최종 졸업 작품 발표 시연의 속도와 안정성을 모두 확보하기 위해 설계한 핵심 시스템 아키텍처의 구조와 흐름은 아래와 같습니다.

```
[React 프론트엔드]
       │
       │ ① 지도의 상권을 그냥 클릭할 때 (기본 정적 조회)
       ▼
[Spring Boot 백엔드] ➔➔➔ ② PostgreSQL DB (predictions & shap_features 테이블) 조회 ➔➔➔ 1ms 내 즉시 반환
       │
       │ ③ 사용자가 슬라이더로 수치 조작 후 [시뮬레이션] 클릭할 때 (가상 연산 발동)
       ▼
[Spring Boot 백엔드] (RestTemplate HTTP 통신으로 데이터 토스)
       │
       ▼
[FastAPI 파이썬 ML 서버] (ml-server/app.py)
       │ ➔ ④ XGBoost & LightGBM 앙상블 모델 실시간 추론 (Predict)
       │ ➔ ⑤ SHAP TreeExplainer로 피처별 실시간 기여도 분해 (Explain)
       ▼
[Spring Boot 백엔드] (JSON 응답 수신 후 React로 패스)
       │
       ▼
[React 프론트엔드] ➔ ⑥ Recharts 막대 그래프 및 게이지 차트 실시간 갱신
```

이 구조는 평상시에는 데이터베이스 조회(Static)로 초고속 서빙을 유지하고, 사용자가 수치를 직접 조절할 때만 실시간 파이썬 머신러닝 연산(Dynamic)을 수행하여 부하를 제어하는 **캐스케이드(Cascade) 하이브리드 아키텍처**입니다.

## 📖 4. [용어 설명 도우미] 핵심 개념 (Metaphor)

### 1. XGBoost + LightGBM 소프트 보팅 앙상블 (Ensemble)

* **직관적 번역**: 상호보완형 AI 협동 예측 모델
* **3초 메타포**: *"내과 전문의와 외과 전문의가 힘을 합쳐 투표로 최종 진단을 내리듯, 두 AI가 서로의 단점을 보완해 예측 정확도를 극대화합니다."*
* **상세 설명**: 수평적으로 트리를 키우는 XGBoost와 수직적(리프 중심)으로 빠르게 키우는 LightGBM을 3:7 비율로 결합(Soft Voting)하여, 단일 모델의 특정 변수 편향성을 극복하고 우수한 일반화 성능을 달성한 기법입니다.

### 2. SHAP (TreeExplainer) 기여도 분석

* **직관적 번역**: 1:1 맞춤형 폐업 위험 요인 진단기
* **3초 메타포**: *"환자의 종합 혈액 검사지에서 어떤 수치가 당뇨 위험을 높였고 낮췄는지 보여주듯, 개별 점포의 어떤 지표가 폐업을 유도했는지 정밀 분석합니다."*
* **상세 설명**: 협동게임이론에 근거한 Shapley Value를 트리 앙상블 모델에 적용하여, 블랙박스 형태의 인공지능 예측 결과를 각 피처별 기여도(log-odds 단위)로 해체하여 보여주는 설명 가능한 AI(XAI) 기법입니다.

### 3. PR-AUC (Precision-Recall AUC)

* **직관적 번역**: 극소수 위험 상점(3%) 정밀 탐지율
* **3초 메타포**: *"서울시 상가 중 실제 폐업하는 곳은 3%에 불과합니다. '아무도 폐업 안 한다'고 우겨서 97%의 야매 정확도를 내는 모델 대신, 진짜 위험한 3%를 얼마나 귀신같이 솎아내는지 측정하는 지표입니다."*
* **상세 설명**: 극심한 클래스 불균형(Imbalanced Data)을 가진 상권 데이터셋에서는 일반적인 Accuracy나 ROC-AUC 지표가 왜곡(Inflation)됩니다. 따라서 소수 클래스인 '폐업 위험 점포'에 대한 정밀도(Precision)와 재현율(Recall) 곡선 아래의 면적을 통해 모델 성능의 신뢰성을 엄밀하게 평가합니다.

### 4. 상권 단위 상대적 밀도 (Density) 변수

* **직관적 번역**: 주변 상권 대비 경쟁 압박 지표
* **3초 메타포**: *"단순히 '유동인구 수'나 '매출 금액'이 많은 대형 상권이라고 무조건 살아남는 것이 아닙니다. 골목의 수요 규모 대비 경쟁 가게가 얼마나 빽빽하게 과포화 상태인지를 측정합니다."*
* **상세 설명**: 원천 데이터의 절대 규모 편향을 해소하기 위해 상권코드(TRDAR_CD)를 기준으로 '점포당 평균 매출 밀도', '유사업종 점포비율', '집객시설 밀도' 등 7종의 상대적 경쟁 압박 파생변수를 설계하여 변동성을 차단하고 성능을 극대화했습니다.

### 5. PostgreSQL 배치 마이그레이션 적재

* **직관적 번역**: 초고속 사전 연산 데이터 적재 서빙
* **3초 메타포**: *"발표 현장에서 무거운 AI 추론 모델을 돌리면 화면 로딩이 멈추거나 지연됩니다. 51.2만 개의 결과를 미리 초고속 계산하여 DB에 저장해 둔 덕분에 화면이 0.001초 만에 뜹니다."*
* **상세 설명**: 시연 안정성을 보장하기 위해 Python 단에서 예측 확률과 SHAP Top5 기여도를 배치(Batch)로 사전 연산하여 Spring Boot JPA 테이블에 Direct BULK INSERT 하는 구조로 서빙 레이어를 단축했습니다.
